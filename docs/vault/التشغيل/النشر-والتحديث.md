# النشر والتحديث

## كيف ينزل تحديث على الموقع؟
Railway **ينشر تلقائياً** أي تغيير يوصل فرع `production`:

```
تعديل الكود  →  دمج في فرع production (GitHub)  →  Railway يبني وينشر تلقائياً  →  jwap.net يشتغل بالنسخة الجديدة
```

## خطوات آمنة للنشر
1. اشتغل على فرع منفصل (`claude/...` أو `fix/...`)، **مو مباشرة على production**.
2. شغّل الاختبارات محلياً وتأكد كلها تنجح.
3. راجع التغيير (أو خلّه يُراجَع) قبل الدمج.
4. ادمج في `production` → Railway ينشر تلقائياً.
5. راقب لوقات الإقلاع (boot logs) للتأكد إن النشر نجح والاتصال رجع.

## تأكيد أن النشر تمّ
- في Railway: آخر deployment للخدمة `web` حالته **SUCCESS** ويشير لآخر commit.
- في اللوق: يظهر إقلاع نظيف + الاتصال يرجع (`connected`).
- أوامر الفحص جاهزة في [[أوامر-مفيدة]].

## تحذيرات مهمة
> [!danger] لا تنشر بعد كل تخمين
> النشر المتكرر يزعزع اتصال واتساب. اختبر محلياً أول، وانشر مرة وحدة بعد التأكد.

> [!warning] احترم القيود
> أي تعديل لازم يكون في **مسار الاتصال فقط** — لا تلمس الحملات/الحصص/الردود/الذكاء الاصطناعي/بوابة الإرسال. التفاصيل في [[القيود-الصارمة]].

## ملاحظة معمارية
- `production` مبني على `master` (السلوك الطبيعي الشغّال) + إصلاحات الباركود.
- فرع `codex/dependency-hardening-shadow-plan` كان يفرض `merchantPolicy` ويعطّل الردود — **لا تعتمد عليه**.
