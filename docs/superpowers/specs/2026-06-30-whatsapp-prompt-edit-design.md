# تعديل البرومنت من الواتساب (عبر قروب التصعيد)

**التاريخ:** 2026-06-30
**الحالة:** تصميم معتمد للمراجعة

## الهدف

تمكين التاجر/الفريق من تعديل برومنت البوت (`config.botInstructions`) مباشرةً من **قروب التصعيد** في الواتساب، بدون الدخول للداشبورد. البوت يفهم التعديل (حتى لو فيه أخطاء إملائية)، يدمجه بذكاء مع التعليمات الحالية، يعرض ملخصاً ويستأذن، وبعد التأكيد يطبّقه فعلياً ويمشي عليه.

## المتطلبات

| # | المتطلب |
|---|---------|
| R1 | أي عضو في **قروب تصعيد معرّف في الإعدادات** يقدر يرسل أمر تعديل. |
| R2 | الأمر يُكتشف بكلمة مفتاحية في بداية الرسالة: `تعديل` / `عدّل` / `عدل` / `برومنت` / `البرومنت` / `ضيف` / `أضف` / `اضف`. |
| R3 | الكشف يتحمّل الأخطاء الإملائية: تطبيع النص العربي + تسامح بحرف واحد (edit-distance ≤ 1). |
| R4 | البوت يدمج التعديل بذكاء (إضافة/تعديل سطر موجود/حذف) ويعيد صياغة التعليمات كاملة بشكل مرتّب. |
| R5 | تدفّق من خطوتين: البوت يعرض ملخص ما فهمه + يستأذن، ولا يطبّق إلا بعد تأكيد `نعم`. |
| R6 | `لا` تلغي التعديل المعلّق؛ انتهاء المهلة (افتراضي ١٠ دقائق) يلغيه تلقائياً. |
| R7 | أوامر التعديل و`نعم/لا` **لا تُرسل للعميل** (لا تتعارض مع جسر التصعيد). |
| R8 | حفظ سجل لكل تعديل (القديم/الجديد/الملخص/مين/متى) لتمكين التراجع لاحقاً. |
| R9 | مفتاح تشغيل/إيقاف للميزة في الداشبورد (افتراضي: مشغّل) + عرض سجل آخر التعديلات. |

## التدفّق (مثال)

```
التاجر:  تعديل: أضف إننا نوصّل للرياض مجاناً والتوصيل لبقية المدن ٢٥ ريال
البوت:   📝 فهمت التعديل:
         • إضافة: التوصيل مجاني للرياض، و٢٥ ريال لبقية المدن.
         بضيف هذي المعلومة بدون ما أغيّر باقي التعليمات.
         أأكّد التطبيق؟ رد بـ (نعم) للتطبيق أو (لا) للإلغاء.
التاجر:  نعم
البوت:   ✅ تم تعديل البرومنت. أمشي عليه من الحين.
```

## المعمارية

### 1. كشف الأمر (Trigger detection)
- **المكان:** مسار رسائل القروب داخل `ingestWhatsappMessage` في
  `src/services/whatsapp/message-ingest.service.js` — **قبل** إسقاط رسائل القروب،
  وبعد/بجانب فحص جسر التصعيد.
- **الشرط:** الرسالة جاية من JID قروب موجود ضمن أهداف التصعيد (`escalationContacts[]`
  اللي هدفها `@g.us`)، **و** الميزة مفعّلة (`config.whatsappPromptEditEnabled !== false`).
- **مطابقة الكلمة المفتاحية:** وحدة مستقلة `lib/prompt-edit-keywords.js`:
  - تطبيع النص: إزالة التشكيل، توحيد `أإآ→ا`، `ة→ه`، `ى→ي`، `ؤ/ئ→ء/ي`، إزالة المسافات الزائدة.
  - قائمة جذور: `["تعديل","عدل","برومنت","البرومنت","ضيف","اضف"]`.
  - تطابق لو أول كلمة في النص تساوي أحد الجذور **أو** ضمن مسافة تحرير ≤ 1 منه.
  - يرجّع `{ matched: boolean, body: string }` حيث `body` = باقي الرسالة بعد الكلمة (والنقطتين إن وجدت).
- لو تطابق → الرسالة تُمرَّر لمعالج التعديل وتتوقّف عن مسار إرسالها للعميل.

### 2. الفهم والدمج الذكي (Smart merge)
- وحدة `src/services/prompt-edit/prompt-edit.service.js`.
- تستخدم نفس موديل المتجر عبر `resolveConfigForAI` + `AIClient` (نفس آلية `ai-worker`).
- ميثود جديدة في `lib/ai-client.js`: `proposePromptEdit(currentInstructions, editRequest)`:
  - بناء برومنت داخلي (meta-prompt) عربي: "هذي التعليمات الحالية للبوت + التاجر يطلب
    هالتغيير → ارجع التعليمات الكاملة بعد تطبيق التغيير (إضافة/تعديل/حذف حسب القصد) مع
    الحفاظ على باقي التعليمات كما هي، + ملخص سطر واحد بالعربي لما تغيّر."
  - يرجّع JSON: `{ newInstructions: string, summary: string }`.
  - لو الموديل رجّع شيء غير صالح → خطأ واضح يُرسَل للقروب ("ما قدرت أفهم التعديل، جرّب صياغة أوضح").

### 3. التخزين (Pending + history)
- جدول جديد `prompt_edit_requests` (migration في `src/db/migrations/init.js`):
  | العمود | النوع | ملاحظة |
  |--------|------|--------|
  | `id` | UUID PK | |
  | `user_id` | UUID FK→users | |
  | `source_jid` | text | قروب التصعيد |
  | `requester_jid` | text | مرسل الطلب |
  | `request_text` | text | نص التعديل الأصلي |
  | `current_instructions` | text | التعليمات قبل التعديل |
  | `proposed_instructions` | text | التعليمات بعد الدمج |
  | `change_summary` | text | ملخص التغيير |
  | `status` | text | `pending` / `applied` / `rejected` / `expired` |
  | `created_at` | timestamptz | |
  | `decided_at` | timestamptz null | |
- "المعلّق" = أحدث صف `pending` لنفس `source_jid` لم تنتهِ مهلته.

### 4. التأكيد (Confirmation)
- في نفس مسار رسائل القروب: لو وصلت رسالة في قروب فيه تعديل `pending` غير منتهٍ:
  - نص يطابق `نعم` (تطبيع/تسامح) → كتابة `proposed_instructions` في
    `config.botInstructions` عبر آلية حفظ الإعدادات الحالية، وضع `status=applied`،
    رسالة تأكيد، **وعدم الإرسال للعميل**.
  - نص يطابق `لا`/`الغاء` → `status=rejected` + رسالة إلغاء.
  - أي رسالة أخرى → تُترك لمسارها الطبيعي (جسر التصعيد) — التعديل المعلّق يبقى حتى تنتهي مهلته.
- تنظيف المنتهية: عند أي قراءة للمعلّق، الصفوف اللي تجاوزت المهلة تُعلّم `expired`.

### 5. الداشبورد (صفحة التصعيد)
- `dashboard/index.html` ضمن قسم التصعيد:
  - مفتاح `whatsappPromptEditEnabled` (checkbox) يُحفظ/يُحمّل مثل بقية الإعدادات.
  - عرض سجل آخر ٥–١٠ تعديلات (مين/متى/الملخص/الحالة) عبر endpoint للقراءة فقط.
- endpoint جديد `GET /api/prompt-edits` يرجّع آخر التعديلات للمستخدم الحالي.

## معالجة الأخطاء
- فشل الموديل / JSON غير صالح → رسالة عربية واضحة في القروب، لا حفظ.
- تعديل ينتج تعليمات فارغة → رفض مع رسالة.
- وصول `نعم` بدون تعديل معلّق → تُتجاهل (تمر لمسارها الطبيعي).
- تعارض تعديلين معلّقين بنفس القروب → الأحدث `pending` هو المعتمد، والأقدم يُعلّم `expired`.

## الاختبارات (TDD)
- **prompt-edit-keywords**: تطابق الجذور، التسامح بحرف، التطبيع، الفصل بين الكلمة والـ body، كشف `نعم/لا`.
- **prompt-edit.service**: اقتراح يحفظ صف `pending`؛ تأكيد يكتب الإعدادات ويضع `applied`؛ إلغاء يضع `rejected`؛ انتهاء المهلة يضع `expired`.
- **التكامل مع مسار القروب**: أمر تعديل لا يُرسل للعميل؛ `نعم` تطبّق؛ رسالة قروب عادية تظل تمر لجسر التصعيد؛ الميزة معطّلة → يُتجاهل الأمر.
- **ai-client.proposePromptEdit**: يرجّع `{newInstructions, summary}` صالح (مع موديل وهمي/mock).

## خارج النطاق (YAGNI)
- التراجع التلقائي (نخزّن البيانات له فقط، بدون أمر `تراجع` الآن).
- التعديل من رقم تصعيد مباشر (DM) — النطاق الحالي قروب التصعيد فقط.
- تعدد لغات الكلمة المفتاحية (عربي فقط الآن).
